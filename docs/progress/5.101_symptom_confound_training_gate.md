# 5.101 Symptom-confound training gate

## Purpose

After the post-hoc controller route failed in 5.99 and 5.100, this note tests whether a training-time mechanism is worth a real run.

Candidate direction:

> Symptom-confound risk equalized KD: use source-domain symptom metadata to define risk groups during KD training, then discourage the student from relying on symptom-correlated shortcuts by matching per-sample training risk across symptom groups.

This is not ordinary symptom fusion. The model is not given symptoms as predictive inputs at inference. Symptoms are treated as a confound/audit variable for training-time risk regularization.

## Novelty boundary

The boundary is narrow:

- Generic consistency regularization, Mean Teacher/self-training, domain adaptation, group invariance, and IRM are existing ideas.
- Recent cough/COVID audio work already emphasizes symptom conditioning, domain adaptation, external validation, and dataset shift.
- Therefore, this candidate is only potentially novel as a cough-specific, symptom-confound negative-transfer guard in KD, not as a new statistical principle.

Useful anchors:

- COVID cough external drift/adaptation risk: https://www.jmir.org/2025/1/e66919/
- Vocal-audio COVID confounding risk: https://www.nature.com/articles/s42256-023-00773-8
- UKCOVID symptom-rich external target candidate: https://www.nature.com/articles/s41597-024-03492-w

## Readiness audit

The audit checks whether source and target symptoms are strong enough to justify a training-time confound regularizer.

Key findings:

| Dataset | rows | symptom nonempty | symptom-only macro OVR AUROC |
| --- | ---: | ---: | ---: |
| Coswara source | 5247 | 0.499142 | 0.738897 |
| COUGHVID | 7310 | 1.000000 | 0.639829 |

Decision flags:

```json
{
  "source_symptoms_available": true,
  "target_symptoms_available": true,
  "source_symptom_only_predictive": true,
  "target_symptom_only_predictive": true,
  "exact_token_overlap": false,
  "semantic_resp_alignment_possible": true
}
```

Interpretation:

- Source symptoms are sparse but strong enough to expose label shortcuts.
- COUGHVID symptoms are fully populated and also predictive.
- Exact token overlap is absent: Coswara uses tokens such as `cough`, `cold`, `fever`, `ftg`, `asthma`; COUGHVID uses structured fields such as `respiratory_condition` and `fever_muscle_pain`.
- Therefore the candidate should use broad semantic risk groups, not exact field matching.

## Source symptom risk groups

The first source grouping maps symptoms into:

- `none`
- `preexisting_only`
- `resp_only`
- `resp_systemic`
- `systemic_only`
- `other_small`

Training split group table:

| group | n | fraction | dominant label prop | readout |
| --- | ---: | ---: | ---: | --- |
| none | 1843 | 0.502043 | 0.818774 healthy | large but strongly label-skewed |
| other_small | 96 | 0.026151 | 0.395833 respiratory_illness | small |
| preexisting_only | 217 | 0.059112 | 0.769585 healthy | usable |
| resp_only | 387 | 0.105421 | 0.348837 covid_positive | usable |
| resp_systemic | 818 | 0.222828 | 0.717604 covid_positive | large but strongly label-skewed |
| systemic_only | 310 | 0.084446 | 0.412903 healthy | usable |

The default 3% hard gate fails only because `other_small` is 2.6%. This is not a fatal blocker; a formal run should either:

- merge `other_small` into the nearest semantic group; or
- drop it from the risk penalty while keeping it in ordinary CE/KD.

- this is not an effect estimate; it only proves the engineering path is runnable.

## Claim status

Not claimable yet.

This is a promising next candidate, but current evidence only supports:

- symptoms are strong confounds in source and COUGHVID;
- source symptom groups can be constructed;
- the training path can run.

It does not yet show external gains.

## Recommended next experiment

Run one full hard-gate experiment, not a grid:

1. Build a cleaner symptom-risk group file that merges/drops `other_small`.
2. Train one conservative symptom-risk equalized KD model:
   - env risk weight: 0.1 or 0.3;
   - sigmoid ramp: 10;
   - same seed 7 first;
   - no threshold grid.
3. Evaluate COUGHVID and TosCOVID.
4. Continue only if:
   - COUGHVID improves over source-only by at least 2 points in the first run; and
   - TosCOVID does not drop below source-only.

If the first full run fails, do not tune blindly. The next better path is UKCOVID/Cambridge audio acquisition or a different representation-level mechanism.
