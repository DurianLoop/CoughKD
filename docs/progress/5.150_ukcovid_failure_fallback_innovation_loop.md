# 5.150 UKCOVID Failure Fallback Innovation Loop

Date: 2026-06-09

## Purpose

The original objective says that if an experiment fails, the loop should return
to literature reading and innovation search rather than overfitting the failed
candidate. The semantic-router package already has success and claim-upgrade
gates, but it did not have a machine-readable fallback route for a failed
UKCOVID third-target result.

## New script

- `scripts/summarize_semantic_router_innovation_fallback.py`

Outputs:

- `runs/semantic_router_innovation_fallback/semantic_router_innovation_fallback.json`
- `runs/semantic_router_innovation_fallback/SEMANTIC_ROUTER_INNOVATION_FALLBACK.md`

Current state:

```text
WAIT_FOR_THIRD_TARGET
```

Current active route:

```text
ukcovid_pre_registered_validation
```

Fallback is not triggered yet because UKCOVID has not been evaluated.

## Failure policy

If the UKCOVID success gate later reports:

```text
THIRD_TARGET_DOES_NOT_SUPPORT_CLAIM
```

then the fallback script will switch to:

```text
FALLBACK_INNOVATION_LOOP_TRIGGERED
```

and the allowed next route becomes:

1. do not tune the semantic router post hoc;
2. do not claim UKCOVID generalization;
3. start a new scoped innovation loop;
4. first try HeAR/Cambridge if access is approved;
5. otherwise reframe to a non-COVID cough/task-shift route such as CODA TB.

Small Virufy/Virufyseg signals remain auxiliary only.

## Integration

- `scripts/build_semantic_router_claim_dossier.py` now includes the innovation
  fallback state in the third-target execution-plan requirement.
- `scripts/audit_semantic_router_goal_completion.py` now includes
  `fallback_innovation_loop` as an explicit completion-audit item.
