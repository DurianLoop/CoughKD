# 5.95 Slice-balanced gate control

## Purpose

This note tests whether the current COUGHVID symptom-slice gate remains a 3-5 point improvement after removing the sample-size weighting advantage of the larger symptom slice. The previous held-out result is promising overall, but a reviewer could ask whether the gain is actually broad across symptom strata or concentrated in one subgroup.

## Protocol

The script repeats the same held-out policy fitting used by the margin-regularized gate:

- target: COUGHVID
- slice: `symptom_resp`
- base method: `source_only`
- train fraction: 0.7
- minimum train examples per slice: 100
- switch margin: 0.02
- repeats: 1000

It reports two metrics:

1. **Overall delta**, the usual sample-weighted macro one-vs-rest AUROC delta.
2. **Slice-macro delta**, the mean of valid per-symptom-slice AUROC deltas, giving `symptom_resp=false` and `symptom_resp=true` equal weight.

## Interpretation

This is a useful tightening result, not a pass.

The original overall improvement remains in the desired 3-5 point range, but the equal-slice control drops to about +1.9 points and has a negative lower confidence bound. The gate is therefore not a broad two-slice improvement. It is mostly a guarded transfer into the `symptom_resp=true` subpopulation while leaving the `symptom_resp=false` group close to the source-only baseline.

This means the safest current claim is narrower than before:

> A target-calibrated transfer gate can detect one clinically meaningful symptom slice where a specialized student should replace the source-only model, while avoiding broad negative transfer elsewhere.

It is still not strong enough for the final ICASSP claim because:

- the evidence is COUGHVID-only;
- the true-symptom slice has a promising mean gain but an unstable confidence interval;
- slice-macro performance does not clear the 3-point target;
- ordinary symptom-conditioned cough modeling is not novel enough because related symptom-aware systems already exist.

## Next decision point

The local code path has squeezed most low-cost evidence out of COUGHVID. Further progress needs one of these routes:

1. **Best scientific route:** obtain Cambridge COVID-19 Sounds / ComParE CCS access and run the existing external onboarding pipeline.
2. **Best public-data route:** authorize the UKCOVID audio acquisition plan, then build embeddings/predictions and rerun the gate with metadata-only and random-slice controls.
3. **Lower-risk auxiliary route:** pursue DiCOVA only as a Coswara-derived auxiliary protocol with overlap control, not as independent validation.

Until one of these second-target routes succeeds, the current innovation remains a strong pilot signal rather than a claimable ICASSP 2027 contribution.
