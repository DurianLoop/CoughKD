# 2026-05-12 实验路线澄清：模型、数据、创新点与第 5 点解释

## 1. 教师模型和学生模型到底要不要重新训练

结论先说清楚：

> PANNs、AST、BEATs、PaSST、AudioMAE 这类 teacher 通常有公开预训练权重；MobileNetV3、BC-ResNet、EfficientNet、DepthwiseStudent 这类 student 通常只是架构或通用预训练模型。真正用于我们咳嗽任务的分类头、蒸馏过程和最终 student 都需要在我们的 cough 数据协议上重新训练或微调。

不要理解成“下载一个现成模型，直接得到我们的结果”。更准确的流程是：

1. 找到模型论文和官方实现，确认输入格式、采样率、特征类型和预训练权重。
2. 加载公开预训练 backbone，例如 AudioSet 上的 PANNs/AST/BEATs。
3. 在 Coswara 或多数据集上接一个 cough classification head，做 linear probe 或 fine-tuning。
4. 得到 teacher 在我们任务上的 logits 和 embedding。
5. 用 teacher 的 logits/embedding/relation 去训练轻量 student。
6. 比较 CE-only student、vanilla KD student 和我们提出的 RACD/CoughKD 方法。

也就是说：

| 类型 | 是否已有预训练权重 | 我们要做什么 |
|---|---|---|
| PANNs CNN14 | 有，AudioSet 预训练 | 加分类头，在 cough 任务上微调或冻结 backbone 训练 head |
| AST | 有，AudioSet 预训练 | 适配 log-mel 输入，在 cough 任务上 fine-tune |
| BEATs | 有，音频表征预训练 | 提取 embedding 或 fine-tune，作为强 teacher |
| PaSST | 有，音频分类预训练 | 作为 transformer teacher 候选 |
| AudioMAE/OPERA 类模型 | 通常有预训练 | 主要看 respiratory/audio representation 能否迁移 |
| DepthwiseStudent | 我们当前已有 | 从头训练，作为极限压缩 student |
| MobileNetV3-small | 有 ImageNet 架构/权重，但音频任务通常需重新训练 | 用 log-mel 当 2D 输入，训练 cough student |
| BC-ResNet | 有音频任务论文/实现 | 按音频分类模型重新训练 |
| EfficientNet-B0 | 有通用架构/权重 | 作为较强小模型 student，重新适配音频 |

因此，不是简单“找论文抄结构”，也不是“拿训练好的模型直接比较”。我们要做的是：

> 利用大模型已有的通用音频表征能力，在我们的 cough 数据和任务协议下重新建立 teacher-student evaluation。

当前代码里的 PANNs CNN14 16 kHz teacher 已经走通了这个思路：它不是 PANNs 原始 AudioSet 527 类任务，而是用 PANNs backbone 加 cough-label head，在 Coswara cough split 上得到我们的 teacher 结果。

## 3. 实验是不是排列组合

不能把实验设计成：

> teacher × student × KD × dataset × metrics 的机械穷举，然后挑一个最高分当 claim。

这样会像调参或 benchmark，不像 AAAI 方法论文。

正确做法是：

> 组合实验只是证明方法有效的证据，不是论文创新本身。

也就是说，我们确实需要比较不同 teacher、student 和 KD baseline，但这些实验应该服务于一个明确的方法问题：

> 在咳嗽音频这种小数据、跨数据集漂移、标签噪声明显的场景下，如何可靠地把大音频模型的表征蒸馏到极小 student，而不是盲目模仿 teacher？

因此主文实验应当收敛成几张核心表：

1. 主结果表：CE-only、vanilla KD、已有 KD baseline、RACD ours。
2. 消融表：去掉 reliability、去掉 embedding KD、去掉 relation KD、去掉 domain loss。
3. 跨数据集表：Coswara test、Coswara to COUGHVID、Coswara to DiCOVA。
4. 效率表：params、FLOPs、model size、CPU latency、retention。
5. Pareto 图：横轴效率，纵轴性能。

完整 teacher/student/KD matrix 可以放 appendix，而不是把它当成论文主线。

## 4. 我们的创新到底是什么

你的理解基本正确：

> 创新不是 PANNs、AST、BEATs、MobileNetV3、BC-ResNet 这些模型本身，也不是最普通的 KL distillation 本身；创新应当是面向 cough audio 的 reliability-aware、cross-domain-aware、deployment-oriented distillation framework。

可以把创新拆成四层。

### 4.1 创新一：问题重定义

不是主张：

> 我们证明咳嗽可以诊断 COVID。

而是主张：

> 我们研究如何把大型音频模型中的 cough/audio representation 可靠地压缩到端侧轻量模型中，并在泛化、校准和效率指标上系统评估。

这个问题重定义本身很重要，因为它避开了“临床诊断有效性”的高风险 claim，把论文放在 representation learning、model compression、audio deployment 的方向上。

### 4.2 创新二：多教师到单学生，而不是平均 ensemble

普通 ensemble 是多个模型投票或平均预测，推理时仍然很重。

我们的目标是：

> 训练时利用多个 teacher，推理时只保留一个极小 student。

这叫 multi-teacher to one-student distillation。

直觉：

- PANNs 可能擅长局部音频事件。
- AST 可能擅长 spectrogram 全局结构。
- BEATs 可能有更强通用音频表征。
- student 不需要部署这些大模型，只需要在训练时从它们那里学习。

最后部署时：

```text
输入 cough audio -> tiny student -> 输出概率
```

teacher 只在训练阶段使用，不进入端侧部署。

### 4.3 创新三：Reliability-aware teacher weighting

多 teacher 不是简单平均。因为每个 teacher 不一定都可靠。

普通做法：

```text
soft_label = average(PANNs, AST, BEATs)
```

问题是：如果某个 teacher 在某些样本上很不确定、校准很差，甚至学到了数据集偏差，平均它反而会污染 student。

我们的做法应当是：

```text
soft_label = weighted_average(PANNs, AST, BEATs)
weight = teacher reliability
```

teacher reliability 可以由这些因素决定：

- confidence：teacher 是否有明确判断。
- entropy：预测分布是否很混乱。
- calibration：teacher 的概率是否可靠。
- teacher agreement：多个 teacher 是否互相一致。
- domain similarity：这个样本是否像 teacher 擅长的数据域。
- quality score：音频质量是否足够好。

核心思想：

> teacher 可靠时多学，teacher 不可靠时少学。

这就是比普通 KD 更有方法贡献的地方。

### 4.4 创新四：Multi-level KD

当前 response KD 增益只有 +0.0025 AUROC，说明只学 logits 不够。

因此要从多个层次蒸馏：

| 层次 | 学什么 | 目的 |
|---|---|---|
| Response KD | teacher logits / soft probability | 学最终类别判断 |
| Embedding KD | teacher penultimate embedding | 学 cough representation |
| Relation KD | batch 内样本相似度矩阵 | 学 teacher 认为哪些样本相似 |
| Prototype KD | 每类或每域的中心表示 | 学类别/数据域的全局结构 |
| Calibration KD | 温度缩放后的概率分布 | 学更可靠的概率输出 |

关键思想是：

> student 不只是模仿 teacher 的答案，而是模仿 teacher 如何组织音频样本之间的表示空间。

这会让论文从“我用了 KD”升级成“我提出了咳嗽音频表征蒸馏框架”。

## 5. 第 5 点：Deployment-oriented evaluation 到底是什么意思

你不太理解的第 5 点，核心是：

> 如果我们的方向是 lightweight deployment，那么论文不能只报告 AUROC/F1，还必须证明 student 真的更小、更快、更适合部署，并且在性能损失可接受的前提下形成更好的效率-性能折中。

### 5.1 为什么只报 AUROC 不够

如果只报：

```text
Teacher AUROC = 0.68
Student AUROC = 0.63
```

审稿人会问：

> 那为什么不用 teacher？

所以你必须同时报告：

```text
Teacher params = 80M
Student params = 20K
Teacher CPU latency = 500 ms
Student CPU latency = 5 ms
Teacher model size = 300 MB
Student model size = 0.1 MB
```

这样论文故事才成立：

> student 性能略低于 teacher，但在参数量、模型大小、延迟、内存和部署成本上大幅优于 teacher。

### 5.2 需要报告哪些部署指标

建议至少报告：

| 指标 | 意义 |
|---|---|
| Params | 参数量，衡量模型大小的基础指标 |
| Model size MB | 保存成 checkpoint/ONNX 后的磁盘体积 |
| FLOPs/MACs | 单次推理计算量 |
| CPU latency | 普通 CPU 上每条音频推理时间 |
| GPU latency | GPU 上吞吐能力 |
| Peak memory | 推理时峰值内存 |
| Throughput | 每秒能处理多少条音频 |
| AUROC retention | student 保留 teacher 多少性能 |

其中 retention 很适合我们的故事：

```text
Retention = Student AUROC / Teacher AUROC
```

当前结果：

```text
Teacher AUROC = 0.6134
KD Student AUROC = 0.5664
Retention = 0.5664 / 0.6134 = 92.3%
```

这句话比单独说 student AUROC 0.5664 更适合压缩论文：

> 在约 3912x 参数压缩下，student 保留了 teacher 约 92.3% 的 AUROC。

但要注意，这不能过度包装，因为当前 teacher 本身还不强。更理想的是找到更强 teacher，再保持较高 retention。

### 5.3 Pareto frontier 是什么

部署论文最核心的图通常是 Pareto frontier。

横轴可以是：

```text
Params / FLOPs / CPU latency
```

纵轴可以是：

```text
AUROC / AUPRC / balanced accuracy
```

每个点代表一个模型：

- PANNs teacher
- AST teacher
- BEATs teacher
- DepthwiseStudent CE-only
- DepthwiseStudent vanilla KD
- MobileNetV3 CE-only
- MobileNetV3 RACD
- BC-ResNet RACD

理想情况下，我们的方法点应该位于更好的位置：

> 在相近参数量下 AUROC 更高，或者在相近 AUROC 下参数更少、延迟更低。

这比一个巨大结果表更有说服力。

### 5.4 为什么这是论文贡献而不是工程附录

因为我们的主线是端侧部署：

> large audio foundation model -> ultra-light cough student

如果不报告部署指标，这个主线就不完整。

AAAI/ICASSP 审稿人会希望看到：

- 性能是否还可以；
- 是否真的轻量；
- 是否比同等大小 baseline 更好；
- 是否有外部泛化；
- 是否有校准；
- 是否有实际推理速度。

因此 deployment-oriented evaluation 不是附属内容，而是支撑论文 claim 的必要证据。

## 6. 当前最推荐的第一阶段实验

先不要急着做全部组合。第一阶段只做最小闭环：

1. 下载并整理 Coswara。
2. 复现现有 PANNs CNN14 teacher + DepthwiseStudent 结果。
3. 跑 3-5 个 random seeds。
4. 补齐 AUROC、AUPRC、macro-F1、balanced accuracy、sensitivity at 95% specificity。
5. 补齐 ECE、Brier score。
6. 补齐 params、model size、FLOPs、CPU latency。
7. 再加入一个 teacher，例如 AST 或 BEATs。
8. 再加入一个 student，例如 MobileNetV3-small 或 BC-ResNet。
9. 再实现 embedding KD 和 relation KD。
10. 最后下载 COUGHVID 或 DiCOVA 做 external validation。

第一阶段的目标不是立刻 SOTA，而是回答：

> 我们的方法问题是否成立？单纯 response KD 是否不足？多层次、可靠性感知蒸馏是否能在效率-性能折中上优于普通 KD？

## 7. 和旧 README 的关系

旧 README 里的方向更宽，原来把 patient-level voiceprint recognition 放在 primary track，把 compression and distillation 放在 fallback track。

现在的想法与旧 README 不是冲突，而是做了收敛：

> 把旧 README 里的 fallback track 提升为当前主线，把 patient voiceprint recognition 降为长期方向或辅助任务。

原因是：

- 声纹识别需要稳定的 subject identity 标签和更严格的验证协议；
- 当前已有代码和结果主要支持 cough classification + distillation；
- AAAI 2027 更需要一个清晰的方法问题，而不是过宽的统一 pipeline；
- reliability-aware cross-dataset distillation 更容易形成方法贡献。

因此当前主线应改写为：

> Reliability-Aware Cross-Dataset Distillation for Ultra-Light Cough Audio Representation Learning and Deployment.

中文：

> 面向端侧部署的可靠性感知跨数据集咳嗽音频表征蒸馏。

## 8. 一句话总结

现在最稳的路线是：

> 先在 Coswara 上复现并做扎实现有 teacher-student-KD pipeline，再引入 COUGHVID/DiCOVA 做外部验证；实验不是为了排列组合找最高分，而是为了证明我们提出的可靠性感知、多层次、跨数据集蒸馏方法，能够把大音频模型的 cough representation 压缩到极小 student，并在性能、泛化、校准和部署效率之间取得更好的折中。

前同学已经做到了一个**可运行的工程闭环**：在 Coswara cough split 上，用 **PANNs CNN14 16 kHz teacher** 蒸馏 **DepthwiseStudent**，并且得到了 teacher、CE-only student、KD student 的部分指标。当前代码里也已经有 response / feature / embedding / relation KD 的接口雏形，比如 [torch_models.py](D:/CoughKD/AAAI/src/coughkd/torch_models.py) 里有 `PannsCnn14Teacher`、`DepthwiseStudent` 和 `torch_kd_loss`。但从已有结果看，还没有真正完成我们现在讨论的创新：**多教师、多教师可靠性权重、跨数据集约束、系统性的 multi-level KD 消融**。

所以旧工作是：

> single teacher + single student + Coswara + 初步 KD baseline

我们要推进成：

> reliability-aware multi-teacher / multi-level / cross-dataset distillation for lightweight cough audio deployment

**关于是否可以不和 SOTA 比 F1**
不能完全不比。更稳的写法是：我们的主 claim 不应该是“F1/AUC 超过所有 COVID 咳嗽诊断模型”，而是：

> 在相近或可接受的性能下，我们显著提升效率、压缩率、推理速度，并且通过跨数据集和校准实验证明更可靠。

也就是说，**性能指标仍要报**，包括 AUROC、AUPRC、macro-F1、balanced accuracy、sensitivity at 95% specificity；但论文主线不是“诊断 SOTA”，而是“效率-性能-泛化-校准的综合折中”。如果只报效率，审稿人会问：小是小了，但还能不能用？所以要用 Pareto frontier 讲故事。

   | BEATs | MobileNetV3-small | 强 teacher + 成熟端侧 student |
   | AST/BEATs ensemble | BC-ResNet | 音频轻量模型强 baseline |
   | PANNs+AST+BEATs | DepthwiseStudent | 验证 multi-teacher RACD |

**和我们方向类似的 KD 创新论文**
这些值得重点读：

1. **EfficientAT / Transformer-to-CNN KD, ICASSP 2023**  
   和我们最接近：大 audio transformer 蒸馏到高效 CNN，强调效率-性能折中。  
   https://research.jku.at/en/publications/efficient-large-scale-audio-tagging-via-transformer-to-cnn-knowle

2. **Respiratory Sound Classification with Ensemble KD, Interspeech 2025**  
   更接近呼吸音医学场景：用 ensemble teacher 蒸馏 student，强调小数据和架构无关。  
   https://www.catalyzex.com/paper/improving-respiratory-sound-classification

3. **Efficient Audio Captioning with Encoder-Level KD, 2024**  
   音频任务里做 encoder-level KD 和 contrastive KD，说明只蒸馏输出不够。  
   https://huggingface.co/papers/2407.14329

4. **Multi-Distillation from Speech and Music Representation Models, 2025**  
   多 teacher / 跨域音频表征蒸馏，和我们的 multi-teacher 思路相近。  
   https://huggingface.co/papers/2506.07237

5. **Relational Knowledge Distillation, CVPR 2019**  
   relation KD 的经典来源：不只学单样本输出，而是学样本之间的结构关系。  
   https://openaccess.thecvf.com/content_CVPR_2019/html/Park_Relational_Knowledge_Distillation_CVPR_2019_paper.html

6. **Contrastive Representation Distillation, ICLR 2020**  
   用 contrastive objective 蒸馏 representation，适合作为 embedding/relation KD baseline。  
   https://iclr.cc/virtual_2020/poster_SkgpBJrtvS.html

7. **Decoupled Knowledge Distillation, CVPR 2022**  
   对 logit KD 做更细拆分，可作为 response KD 的强 baseline。  
   https://cir.nii.ac.jp/crid/1871991017817303808?lang=en

最终论文故事可以这样定：

> 继承工作已经验证了 PANNs-to-DepthwiseStudent 在 Coswara 上的初步可行性，但它只是 single-teacher vanilla KD baseline。我们进一步提出 reliability-aware cross-dataset multi-level distillation，把多个大音频 teacher 的表征可靠地压缩到极小 student 中，并通过跨数据集泛化、消融实验和效率-性能 Pareto frontier 证明方法价值。

这个故事是连贯的，也比“找一个组合刷最高分”更像 AAAI 方法论文。
