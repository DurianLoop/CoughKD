# 5.45 External Dataset Access Re-check

## 目的

CoughKD-ShiftAudit 当前最大的证据缺口不是再多做一个 KD 变体，而是缺少第二个足够大的独立外部目标。因此本轮重新核实 Cambridge / ComParE 与 DiCOVA 的可获得性，并决定下一步行动。

## Cambridge COVID-19 Sounds / ComParE CCS

当前判断：仍然是最高优先级第二外部目标。

原因：

- Cambridge COVID-19 Sounds / NeurIPS Datasets release 报告了大规模多模态音频数据，包含 cough、breathing、voice。
- 相比 Virufy 的 16 个 clinical cough recordings，Cambridge 的规模更适合支撑 ICASSP 主线。
- 它与 Coswara 相对独立，更适合作为第二 external validation target。

限制：

- 当前不是简单 GitHub/网页直下数据。
- 官方说明这是敏感数据，需要 formal Data Access / Data Transfer Agreement。
- 申请邮箱为 `covid-19-sounds@cl.cam.ac.uk`。

行动：继续把 Cambridge 作为主线必争取数据；已有 `docs/external_data_request_pack.md` 可以直接用于申请。

## DiCOVA

当前判断：可以做辅助协议，但不能替代 Cambridge。

原因：

- DiCOVA 2021 Track-1 是 cough COVID detection challenge，使用 AUC 作为关键指标。
- 官网显示 challenge 已关闭，数据曾发送给注册队伍。
- 数据与 Coswara 有关联，因此即使拿到，也需要做 overlap control，不能直接说是完全独立外部验证。

行动：DiCOVA 作为第三优先级。拿到数据后使用 `scripts/build_external_cough_manifest.py` 构建 manifest，并检查 Coswara overlap。

## 结合当前实验的结论

当前已有：

1. COUGHVID：主要 large external target；
2. Virufy original：tiny stress target，16 条 clinical cough；
3. Virufy segmented：121 clips，但仍为 16 source subjects；
4. Virufy segmented subject-level audit：证明 clip-level 和 subject-level method ranking 会变化。

这足够支撑一个“failure-oriented audit protocol”的雏形，但还不够支撑 ICASSP main-track 强投稿。要达成更稳的 claim，下一步必须优先解决 Cambridge 或另一个大规模独立外部目标。

## 下一步

1. 使用 `docs/external_data_request_pack.md` 给 Cambridge 发送数据申请。
2. 并行寻找 DiCOVA/CodaLab 历史下载入口，但只作为 auxiliary protocol。
3. 在等待数据期间，先把当前 COUGHVID + Virufy stress target 的图表整理成可投稿草稿结构。
4. 不继续无边界做 teacher × student × KD 穷举。
