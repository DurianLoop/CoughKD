# 5.132 Third-target all-slice diagnostic boundary

## Purpose

Continue hardening the UKCOVID third-target pre-registration. The previous
success gate required an all-slice control artifact, but did not explain how
that control should be interpreted under the current semantic-router
implementation.

## Implementation fact checked

The router chooses a strategy from the target's registered `slice_column`:

```text
scripts/audit_target_calibrated_transfer_controller.py
```

Current UKCOVID config:

```text
slice_column = symptom_cough_any
```

And:

```text
scripts/audit_semantic_constrained_transfer_router.py
```

uses `_choose_strategy(target, semantic_slice_columns)` to check whether that
registered `slice_column` is present in the semantic whitelist. It does not
search across every provided metadata column for a best slice.

## Consequence

For UKCOVID, an all-slice whitelist includes `symptom_cough_any`, so it may
match the main semantic rule. Therefore all-slice is still required as a
diagnostic artifact, but equality with the main semantic run is not a hard
failure. The hard control-separation criteria remain:

1. demographic-only control does not match the main semantic rule;
2. no-slice control does not match the main semantic rule.
