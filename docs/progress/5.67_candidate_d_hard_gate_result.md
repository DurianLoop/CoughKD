## Engineering Fix Before Gate

The first PANNs training attempt stalled during teacher construction. Diagnosis found the blocker in `torchlibrosa` STFT initialization:

- `Spectrogram(...)` stalled during its librosa window path.
- Pure NumPy DFT matrix creation was fast.
- The slow path was avoided by patching `src/coughkd/torch_models.py` with a local torchlibrosa initialization fast path:
  - fixed Hann window generation with NumPy;
  - local pad-center fast path;
  - local mel filter initialization;
  - fast DFT matrix generation.

## Verdict

Candidate D fails the hard gate.

It should not be expanded to seeds 11/23 and should not be tuned further as a method-claim route.

Reason:

- It does not reach the COUGHVID threshold.
- It is negative relative to COUGHVID source-only.
- It does not reach the Tos threshold.
- It remains below Tos CE post-hoc.

This result supports the existing ShiftAudit / failure-cartography paper direction, but not a new method-superiority claim.

## Next Innovation Loop

Do not continue active-cough selective KD by small hyperparameter tuning.

Next loop should return to literature-guided candidate search. High-value directions to scout next:

1. **Cached teacher-response diagnostics**: analyze whether teacher confidence / entropy / margin on source examples predicts external transfer failure before using it as KD pressure.
2. **Evaluation-unit aware distillation**: look for literature on subject/clip aggregation mismatch and design losses that optimize subject-stable predictions rather than clip-only logits.
3. **Foundation-feature freezing vs head-only student alignment**: investigate whether the ultra-light student bottleneck, not KD weighting, is the limiting factor.
4. **External-target data quality routing**: read recent work on noisy public cough labels and target-quality filtering, with strict guardrails to avoid target-label leakage.

Any next candidate must again pass a seed-7 hard gate before expansion.
