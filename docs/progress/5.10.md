# 2026-05-10 研究定位与阶段进展

## 1. 当前研究方向共识

当前项目不应再把“咳嗽声音是否真的可以临床诊断 COVID-19”作为主战场。这个 claim 太强，医学敏感度高，而且很容易受到混杂因素、标签噪声、招募偏差、设备差异和外部验证不足的质疑。

更合适的研究定位是：

> **Representation learning + lightweight deployment for cough audio via knowledge distillation**

中文可以表述为：

> **面向咳嗽音频筛查的高效表征蒸馏与轻量化部署。**

核心研究问题应该是：

> 大型预训练音频模型可能已经学到了一定的 cough/audio representation。我们能否通过知识蒸馏，把这些表征能力迁移到一个极小的 student model，使其在保持可接受筛查性能的同时，大幅降低参数量、模型体积、FLOPs、推理延迟和部署成本？

这个问题比“证明咳嗽中存在可靠 COVID 声学生物标志物”更稳、更可控，也更符合当前已有实验基础。

## 2. 不应该主张什么

当前阶段不应该主张：

- 咳嗽音频可以临床诊断 COVID-19。
- 模型发现了可靠的 COVID 声学生物标志物。
- 单个 Coswara 实验可以证明临床有效性。
- 某个 split 上 AUC 更高就证明真实筛查价值。
- PANNs + DepthwiseStudent 本身是全新的模型架构。

如果这样写，审稿人会立刻追问：

- COVID 标签是否 PCR confirmed？
- 阳性和阴性样本是否来自相同招募渠道？
- 模型学到的是 COVID，还是症状、咳嗽严重程度、地区、设备或数据集偏差？
- 是否控制了年龄、性别、地区、录音设备、语言、症状和采集协议？
- 是否有 external validation？
- 是否超过了 symptoms-only baseline？
- 在真实筛查工作点下是否有 clinical utility？

Nature Machine Intelligence 2024 那篇 confounding paper 是一个重要警告：音频模型在未调整时可能有较高 AUC，但控制症状和其他混杂因素后性能会明显下降。因此，直接主张“咳嗽可诊断 COVID”风险很高。

## 3. 应该主张什么

更合适的主张是：

> 现有咳嗽 COVID 筛查研究常强调诊断性能，但这些结论容易受到混杂因素、标签噪声和数据集偏差影响。本文不主张发现 COVID 声学生物标志物，而是研究一个更可控、更工程化的问题：如何将大型预训练音频模型中的咳嗽表征蒸馏到超轻量学生模型中，并在端侧部署指标、泛化能力和校准可靠性方面系统评估。

可以考虑的论文题目方向：

> CoughKD: Reliability-Aware Foundation-to-Edge Distillation for Efficient Cough Audio Screening

中文理解：

> CoughKD：面向高效咳嗽音频筛查的可靠性约束基础模型到端侧模型蒸馏。

## 4. 当前已有实验说明了什么

当前实验已经说明 pipeline 是可行的：

| 项目 | 当前结果 |
|---|---:|
| 数据 | Coswara cough-heavy + cough-shallow |
| 样本数 | 5,247 条 |
| subject 数 | 2,635 |
| 划分方式 | subject-disjoint split |
| Teacher | PANNs CNN14 16 kHz |
| Teacher 参数量 | 约 81M |
| Teacher test macro OVR AUROC | 0.6134 |
| Student | DepthwiseStudent |
| Student 参数量 | 20.7k |
| CE-only student AUROC | 0.5639 |
| KD student AUROC | 0.5664 |
| KD 相比 CE-only 增益 | +0.0025 |
| 参数压缩比 | 约 3912x |
| AUROC retention | 约 92.3% |

这些结果可以支持一个谨慎说法：

> 初步实验显示，在极高压缩率下，一个超轻量 student 可以保留一部分 teacher 的性能。然而，当前 response-level KD 的绝对增益很小，说明单纯 logit distillation 不足以充分迁移 cough representation。

这些结果还不能支持更强说法：

> KD 显著提升了轻量咳嗽筛查模型。

## 5. 为什么参数压缩是亮点

当前参数压缩是项目最强的部署信号之一：

```text
PANNs teacher:      约 81,000,000 参数
DepthwiseStudent:   约 20,700 参数
压缩比:             约 3912x
```

这对 deployment-oriented paper 很重要，因为可以强调：

- 模型更小；
- 存储成本更低；
- 推理延迟更低；
- 能耗更低；
- 更容易部署到手机、可穿戴设备或边缘设备；
- 音频可以本地处理，隐私风险更低。

但是，压缩率本身还不够。必须证明：

> 压缩之后性能没有掉太多，或者相比同等大小 baseline 有优势。

## 6. 为什么当前 KD 还不够

当前 KD 的提升是：

```text
0.5664 - 0.5639 = +0.0025 AUROC
```

这个提升太小，可能来自随机种子、训练波动或数据划分波动，不一定是真正的 KD 效果。

因此当前结果更合理的解释是：

> Response KD alone is limited.

中文：

> 单纯输出层蒸馏效果有限，需要进一步做多层次表征蒸馏。

这正好自然引出下一步方法创新。

## 7. Multi-level KD 计划

下一步方法贡献应该是 multi-level KD，而不是只做 response/logit KD。

总损失可以写成：

```text
L = L_CE
  + alpha * L_response
  + beta  * L_feature
  + gamma * L_embedding
  + delta * L_relation
```

### 7.1 Response KD

student 学 teacher 的 logits 或 soft probability distribution。

优点：

- 简单；
- 实现容易；
- 不需要对齐中间层。

缺点：

- 信息量有限；
- 只传递最终答案；
- teacher 如果本身不强，帮助可能很小；
- 对极小 student 来说，可能不足以改变内部 representation。

### 7.2 Feature KD

student 学 teacher 的中间特征。

例如 teacher 输出 2048-d feature，student 输出 128-d feature，可以加一个 projection head：

```text
L_feature = MSE(P(h_student), h_teacher)
```

它的直觉是：

> 不只模仿 teacher 的答案，还模仿 teacher 理解咳嗽音频的方式。

### 7.3 Embedding KD

student 对齐 teacher 的 penultimate embedding。

这对当前方向很重要，因为我们真正想迁移的是：

> cough audio representation

而不只是 COVID 输出概率。

### 7.4 Relation KD

Relation KD 不要求每个样本的 feature 完全一致，而是要求 student 学到 teacher 认为的样本间关系。

例如一个 batch 中，teacher 认为：

- 样本 A 和 B 很相似；
- A 和 C 不相似；
- D 和 E 属于相近模式。

Relation KD 要求 student 保持类似的 pairwise cosine similarity matrix 或 distance structure。

这对小数据和噪声标签尤其有用，因为它迁移的是结构信息。

### 7.5 Full KD

最终需要比较：

- CE-only；
- response KD；
- feature KD；
- embedding KD；
- relation KD；
- full KD。

目标 claim 是：

> 输出层蒸馏不足以迁移 cough representation，多层次 KD 能在极高压缩率下更好地保留 teacher 的音频知识。

## 8. 为什么需要 Teacher 对比

当前只有 PANNs CNN14 这个 foundation teacher。它是 AudioSet 预训练的通用音频模型，不一定最适合咳嗽音频。

需要比较的 teacher：

| Teacher | 作用 |
|---|---|
| PANNs CNN14 | 稳定 baseline teacher |
| AST | spectrogram transformer teacher |
| BEATs | 强预训练音频表征 teacher |
| PaSST | 高性能 audio spectrogram transformer |
| AudioMAE / OPERA-style teacher | 可选 respiratory/foundation 方向 |

Teacher 对比回答的问题是：

> 哪种大型音频模型最适合作为 cough representation teacher？

如果 AST 或 BEATs 能把 teacher AUROC 从当前 0.6134 提升到 0.68 或 0.70，整个蒸馏故事会明显更稳。

## 9. 为什么需要 Student 对比

DepthwiseStudent 的优点是极小，但只有一个 student 不够。

需要比较的 student：

| Student | 作用 |
|---|---|
| DepthwiseStudent | 极限压缩点 |
| MobileNetV3-small | 成熟端侧 CNN baseline |
| BC-ResNet | audio-specific compact CNN |
| EfficientNet-B0 | 更强的小型 spectrogram CNN |
| tiny CNN baseline | 最小基础对照 |

Student 对比回答的问题是：

> KD 的收益是否能跨模型容量稳定存在，而不是只对某一个 student 有效？

最终应该画一个 efficiency-performance Pareto frontier：

```text
x 轴: params / FLOPs / latency
y 轴: AUROC / AUPRC
点: 不同 student 的 CE-only 和 KD 结果
```

这是 deployment-oriented paper 的核心图之一。

## 10. 必须报告的效率指标

因为主线是 lightweight deployment，论文不能只报 AUROC。

必须报告：

- 参数量；
- 模型大小；
- FLOPs / MACs；
- CPU latency；
- GPU latency；
- memory footprint；
- throughput；
- teacher-student AUROC retention。

其中 teacher-student retention 很适合当前方向：

```text
Retention = Student AUROC / Teacher AUROC
```

当前结果：

```text
0.5664 / 0.6134 = 92.3%
```

比较理想的目标是：

> 在大幅压缩参数的同时，达到至少 95% teacher AUROC retention。

## 11. 必须报告的可靠性指标

因为咳嗽筛查有医学敏感性，评估必须比普通分类任务更谨慎。

建议报告：

- AUROC；
- AUPRC；
- macro-F1；
- balanced accuracy；
- sensitivity at 95% specificity；
- specificity at fixed sensitivity；
- bootstrap 95% CI；
- ECE；
- Brier score；
- reliability diagram；
- subgroup AUROC；
- external AUROC drop。

Calibration 很重要，因为 AUROC 只看排序能力，不看概率是否可靠。筛查场景里，模型的概率输出是否可信同样关键。

## 12. External Validation 计划

只在 Coswara 上做不够，必须至少补一个 external validation，否则很容易被认为是 single-dataset overfitting。

候选方案：

- train on Coswara, test on COUGHVID；
- train on Coswara, test on DiCOVA；
- train on COUGHVID, test on Coswara；
- train on Coswara + COUGHVID, test on DiCOVA；
- 如果多个数据集都能拿到，可以做 leave-one-dataset-out evaluation。

external 结果不一定必须很高，关键是诚实报告：

- in-domain performance；
- external performance；
- external AUROC drop；
- calibration shift；
- subgroup variation。

## 13. 下一阶段实验优先级

### 第一阶段：把当前结果做扎实

1. 固定 subject-disjoint split；
2. 跑 3-5 个 random seeds；
3. 报告 mean +/- std；
4. 补 AUPRC、macro-F1、balanced accuracy；
5. 补 ECE 和 Brier score；
6. 测 params、model size、FLOPs 和 latency。

目标：

> 判断当前 +0.0025 AUROC 的 KD 增益是真实趋势还是随机噪声。

### 第二阶段：提升 Teacher

优先级：

1. PANNs CNN14；
2. AST；
3. BEATs；
4. PaSST / AudioMAE / OPERA-style respiratory foundation model。

目标：

> 找到更强的 cough representation teacher。

### 第三阶段：Multi-level KD

优先级：

1. CE-only；
2. response KD；
3. embedding KD；
4. response + embedding KD；
5. relation KD；
6. full KD。

目标：

> 证明 representation-level KD 比 logit-only KD 更能迁移有用的 cough knowledge。

### 第四阶段：Student Family

比较：

1. DepthwiseStudent；
2. MobileNetV3-small；
3. BC-ResNet；
4. EfficientNet-B0。

目标：

> 构建 efficiency-performance Pareto frontier。

### 第五阶段：External Validation

至少补一个外部数据集：

- COUGHVID；
- DiCOVA；
- UK PCR-referenced vocal audio，如果能申请到。

目标：

> 证明我们做的是 reliability-aware evaluation，而不是单一数据集过拟合。

## 14. 最终论文故事线

最终论文可以这样讲：

> 现有 cough-based COVID screening 研究常强调诊断性能，但这种 claim 容易受到混杂因素、标签噪声和数据集偏差影响。本文不主张发现 COVID 声学生物标志物，而是研究一个 deployment-oriented representation learning 问题：如何将大型预训练音频模型中的 cough audio knowledge 迁移到 ultra-lightweight student model。CoughKD 系统比较 teacher choices、student capacities 和 multi-level distillation losses，并在 subject-disjoint、external、efficiency-aware 和 calibration-aware 协议下评估。

最核心的一句话：

> **我们不是证明 cough 可以诊断 COVID，而是研究 cough audio representation 如何被高效蒸馏和部署。**

## 15. 当前阶段结论

当前工作和修正后的研究方向是一致的。

当前状态：

- pipeline 已经打通；
- 数据处理和 subject-disjoint split 已经具备；
- PANNs-to-DepthwiseStudent 蒸馏已经端到端验证；
- 极高参数压缩率已经是一个明显的 deployment 信号；
- 当前 KD 增益太小，需要进一步提升；
- external validation 和 reliability metrics 还缺失。

下一步：

> 从工程可行性推进到可发表证据：提升 teacher，加入 multi-level KD，比较 student family，并系统报告效率指标与可靠性指标。
