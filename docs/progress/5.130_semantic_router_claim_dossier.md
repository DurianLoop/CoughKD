# 5.130 Semantic-router claim dossier

## Purpose

Continue toward a defensible ICASSP 2027 claim by consolidating the current
semantic-router evidence into a requirement-level dossier. This is a low-cost
audit step: it reads existing artifacts and does not run new experiments.

## Added

```text
scripts/build_semantic_router_claim_dossier.py
runs/semantic_router_claim_dossier/SEMANTIC_ROUTER_CLAIM_DOSSIER.md
runs/semantic_router_claim_dossier/semantic_router_claim_dossier.json
```

The dossier reads:

- semantic-router main/negative-control tables;
- paired bootstrap against semantic controls;
- guard-sensitivity CSV;
- novelty matrix;
- ICASSP 2027 official-status note;
- semantic-router submission readiness JSON;
- UKCOVID execution pack.

## Refresh order

Because the dossier reads the readiness JSON and the readiness gate requires the
dossier artifacts, use this order after future evidence changes:

1. Run the relevant evidence-generating scripts.
2. Run `scripts/audit_semantic_router_submission_readiness.py`.
3. Run `scripts/build_semantic_router_claim_dossier.py`.
4. Run `scripts/audit_semantic_router_submission_readiness.py` again.

This keeps both the dossier and the readiness report aligned.

## Current impact

The package now has a single machine-generated claim dossier that says exactly
what is supported, what is explicitly not claimed, and what remains blocking.
It does not complete the overall objective because UKCOVID third-target
validation and final ICASSP 2027 author-kit verification remain unresolved.
