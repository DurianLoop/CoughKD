# 5.168 Protocol Strength vs Nested Controller

Date: 2026-06-16

Constraint: use existing local datasets and artifacts only. Do not run
unapproved inference, training, or downloads.

## Motivation

The current semantic-router claim is strongest if it can answer a reviewer
question:

> Why is this not just ordinary target-calibrated model selection?

Existing artifacts already include a nested target-calibrated controller that
chooses among:

- source-only inference;
- calibration-best single model;
- logistic stacking;
- metadata slice gate.

This step turns those artifacts into an explicit protocol-strength gate.

## Evidence

Semantic router vs nested controller paired bootstrap:

- COUGHVID: semantic minus controller = +0.71 pp, 95% CI [0.42, 1.01],
  P(mean <= 0) = 0.0000.
- TosCOVID: semantic minus controller = +1.90 pp, 95% CI [1.47, 2.34],
  P(mean <= 0) = 0.0000.

Generic nested controllers remain weaker as standalone claims:

- default controller does not clear the all-large-target 3 pp gate;
- threshold1/margin variants also do not clear the all-large-target 3 pp gate;
- selection counts show COUGHVID often chooses `slice_gate`, while TosCOVID
  often chooses `logistic_stacking`, consistent with the semantic-router story.
