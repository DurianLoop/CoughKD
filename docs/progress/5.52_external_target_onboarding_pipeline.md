# 5.52 External Target Onboarding Pipeline

## 本轮目的

当前 blocker 是第二个大外部目标。为了让 Cambridge / CODA TB / DiCOVA 一旦拿到就能直接进入证据链，本轮新增一键 onboarding 流程，避免手动漏掉 overlap audit、summary、paper table 或 readiness gate。

## 新增脚本

```text
scripts/onboard_external_target.py
scripts/onboard_external_target_windows.cmd
```

## 它做什么

给定一个 CoughKD-style manifest 和 target tag，脚本按固定顺序执行：

1. `audit_manifest_overlap.py`：和 Coswara source manifest 做 overlap-control；
2. `evaluate_external_model_set.py`：用已训练的 8 methods × 3 seeds 在新 target 上评估；
3. 可选 `aggregate_external_predictions_by_subject.py`：对 segmented target 做 subject-level 聚合；
4. `summarize_coughkd_guard_multitarget.py`：更新多目标 guard audit；
5. `build_multitarget_shift_audit_table.py`：更新 multi-target table；
6. `build_shift_audit_paper_tables.py`：更新论文 LaTeX/Markdown 表格；
7. `audit_submission_readiness.py`：重新判断是否达到 ICASSP-strength。

它不会训练新模型，也不会做 teacher × student × KD 的无边界搜索。

## 使用方式

```powershell
cd D:\CoughKD\AAAI
D:\conda\envs\CoughKD\python.exe scripts\onboard_external_target.py `
  --manifest manifests\TARGET_external.csv `
  --target-tag TARGET `
  --skip-existing `
  --device auto `
  --batch-size 16
```

Windows 包装命令：

```powershell
scripts\onboard_external_target_windows.cmd manifests\TARGET_external.csv TARGET
```

如果是 segmented target，需要 subject-level 聚合：

```powershell
D:\conda\envs\CoughKD\python.exe scripts\onboard_external_target.py `
  --manifest manifests\TARGET_external.csv `
  --target-tag TARGET `
  --skip-existing `
  --subject-aggregate
```

如果目标可能和 Coswara 重叠，并且音频文件都在本地：

```powershell
D:\conda\envs\CoughKD\python.exe scripts\onboard_external_target.py `
  --manifest manifests\TARGET_external.csv `
  --target-tag TARGET `
  --skip-existing `
  --enable-hash-overlap
```

## Dry-run 验证

已用 Virufy manifest 跑 dry-run：

```powershell
D:\conda\envs\CoughKD\python.exe scripts\onboard_external_target.py `
  --manifest manifests\virufy_external.csv `
  --target-tag dryrun_virufy `
  --skip-existing `
  --dry-run
```

结果：

- overlap audit 命令正确生成；
- external evaluation dry-run 展开为 24 个命令；
- 后续 summary/table/readiness 命令正确列出；
- 没有实际重跑模型。

## 当前意义

这一步把“拿到第二外部集之后怎么做”变成了可执行 pipeline。后续只要拿到 Cambridge / CODA TB / DiCOVA 并构建 manifest，就可以直接运行 onboarding，然后看 `runs/submission_readiness/SUBMISSION_READINESS.md` 是否从 conditional go 变成 go。
