# 5.34 Source-Relative CoughKD-Guard 审计

## 本轮目标

上一轮 CoughKD-Guard 只使用 target-unlabeled 的目标域预测统计，例如平均置信度、熵、COVID 概率、预测类别比例等。该信号在 COUGHVID slice stress test 中表现保守，但不够强：

- 固定 guard 基本总是选择 `tcd_conf035`；
- `age_old` slice 仍然发生负迁移；
- leave-one-slice-out 学习器没有真正学到可迁移选择规则。

本轮尝试加入 **相对于 source-only 模型的目标域预测漂移特征**，验证一个更具体的假设：

> 如果某个 KD/迁移方法在目标域上相对 source-only 产生过大的预测漂移，它更可能引入 teacher shortcut 或目标域不稳定性；反之，适度且一致的漂移可能对应更可靠的收益。

## 新增信号

在 `scripts/summarize_coughvid_slice_guard.py` 中加入每个 method 相对于同 seed `source_only` 的 source-relative 特征：

| Signal | 含义 |
|---|---|
| `agree_source_only` | 与 source-only 预测标签一致的比例 |
| `l1_to_source_only` | 与 source-only softmax 概率的平均 L1 距离 |
| `confidence_gap_source_only` | 目标方法置信度减去 source-only 置信度 |
| `entropy_gap_source_only` | 目标方法熵减去 source-only 熵 |

然后将这些特征加入 `scripts/learn_coughkd_guard_from_slices.py` 的 leave-one-slice-out 线性 guard 学习器中。

## 判断

本轮结论是 **CoughKD-Guard 的当前 source-relative 选择器不成立**。

它相比 vanilla KD 的平均结果仍略好，但这不是可以 claim 的方法贡献，原因是：

1. 固定 guard 仍然退化成几乎总选 `tcd_conf035`；
2. LOSO 学习器加入 source-relative 特征后没有提高稳定性，反而出现 2/9 个负迁移；
3. 平均 selected macro delta 为负，无法满足“自动选择方法避免负迁移”的核心主张；
4. 目前只有 COUGHVID 内部 slice 作为 proxy target，还没有独立外部目标数据集支撑。

## 下一步

停止把当前 CoughKD-Guard 包装成方法创新。下一轮应该转向查新和重新定义更可验证的创新问题：

1. 继续查找 2024-2026 年 label-free model selection、source-free/test-time adaptation、domain generalization、negative transfer detection、KD under distribution shift 相关论文；
2. 判断是否存在更强且可实现的中等工作量方案，例如：
   - 不做“方法选择器”，改做 **KD failure diagnosis benchmark/protocol**；
   - 使用 teacher-student disagreement 的可解释审计，而不是让它直接驱动训练；
   - 构造数据级 shortcut intervention，例如按录音质量/设备/症状 proxy 做分层反事实评估；
   - 转向分析型论文：`When Does KD Help or Fail for Ultra-Light Cough Audio Models under Dataset Shift?`
3. 若要继续方法路线，必须先拿到至少一个独立外部数据集，否则任何 target-unlabeled selection claim 都会被认为证据不足。
