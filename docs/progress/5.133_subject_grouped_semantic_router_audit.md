# 5.133 Subject-Grouped Semantic-Router Audit

Date: 2026-06-09

## Why this audit was needed

The semantic-router claim now has an explicit subject-overlap check. Row-level
target calibration/evaluation splits are acceptable for COUGHVID because the
manifest has one row per subject, but they are risky for multi-record targets:

- COUGHVID: 7310 rows / 7310 subjects, no multi-record subjects.
- TosCOVID: 991 rows / 495 subjects, 336 multi-record subjects.
- UKCOVID: 22242 rows / 11121 subjects, all subjects have two recordings.

For TosCOVID and future UKCOVID evidence, claim-relevant runs must therefore
use `--group-split-column subject_id`.

Interpretation: subject-grouped resampling preserves the intended semantic
pattern. COUGHVID is unchanged. TosCOVID drops from the row-level +3.99pt mean
gain to +2.94pt and has higher split-tail risk, but the semantic rule remains
well above inverted and all-slice controls.

## Claim boundary update

Use the subject-grouped TosCOVID result as the conservative evidence boundary
for multi-record targets. The row-level TosCOVID +3.99pt result remains useful
as an earlier diagnostic but should not be the only quoted evidence for the
claim.

UKCOVID post-download runs and the third-target success gate were updated to
require `--group-split-column subject_id`; without that setting, UKCOVID should
not upgrade the ICASSP claim.
