## Interpretation

UKCOVID is a strong candidate for the next external validation target because it has large, balanced-enough metadata slices and a high subject count. However, the strongest symptom fields are also strong label proxies. This creates a serious confounding risk: a gate that appears to improve covid detection might simply be exploiting the target dataset's symptom-label correlation.

The current innovation boundary should therefore stay narrow:

> metadata-available, target-calibrated negative-transfer gating across clinically meaningful symptom slices.

It should not be framed as cough-only covid acoustic diagnosis, and it should not be framed as generic metadata fusion.

## Required controls before a claim

Once UKCOVID audio is available, the validation should include:

1. Source-only audio baseline on UKCOVID.
2. Candidate B / Candidate F / current specialized students on the same UKCOVID embeddings.
3. Margin-regularized symptom-slice gate with nested or held-out margin selection.
4. Metadata-only baseline using the same symptom fields.
5. Random matched slice negative controls, as in the COUGHVID control.
6. Symptom-only and symptom-stratified reporting so gains are not confused with symptom-label priors.

## Current claim status

Not claimable yet.

The COUGHVID margin-gated result remains the strongest local signal, but UKCOVID currently contributes only readiness evidence because the audio files are missing. The next low-token, low-risk step is to either:

- keep searching for another metadata-rich external dataset with already available audio/embeddings, or
- ask the user whether to authorize the large UKCOVID audio acquisition path.
